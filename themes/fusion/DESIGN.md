# 一线 · 同心：设计与维护

## 概念与阅读路径

这是一封亲手打开的长信。照片成为书封，姓名下的一根红线穿接照片与纸笺，从白昼走过暮色，在夜里相系成结。接着展开心意，让完整圆环围住邀请语，最后交给宾客一张可以保存的正式邀请。

页面统一使用“一线 · 同心”。暖纸、朱红、照片和既有书写字体构成基础；夜色服务于相系章节，纸粒保持静止。阅读路径共六章：

| 章节      | 设计与交互                                                                                           |
| --------- | ---------------------------------------------------------------------------------------------------- |
| 01 / 展信 | 完整照片沿左侧书脊向左打开，露出固定内页；姓名下方留一条平静红线                                     |
| 02 / 牵线 | 红线传说引入五张照片与五种纸笺；照片上下中心穿接，四处留白依次画出松结、双线交叠、柔和心形与开口椭圆 |
| 03 / 相系 | 黄昏平线与完整夜结分别停靠，白昼纸色与夜色随滚动简单淡入淡出，保留长线尾、婚讯和邀请原文             |
| 04 / 心意 | 两张纸页扇形展开，可放大读原文                                                                       |
| 05 / 圆满 | 到达即呈现完整圆环与全部邀请文字，随章节自然离场；手机、桌面及减少动态效果模式一致                   |
| 06 / 敬邀 | 清楚呈现日期、两段时间、地点、地图和红线双环 PNG                                                     |

宾客使用原生纵向滚动或固定箭头阅读；箭头停在完整的照片或章节状态，真实到达文档底部才显示返回状态。日期、时间和地点集中在正式邀请，原独立赴约章节 `TheDay`、对应文案及 `our-day.webp` 已移除。页面没有背景音乐、粒子或回执表单。

## 封面与固定内页

`OpeningCover.tsx` 将 `.cover-page` 内页与 `.cover-sheet` 封面并列放置。`CoverFront.tsx` 在一张连续纸面上渲染完整响应式照片；`app/cover.css` 将透视原点和旋转原点放在 `left center`，封面从 0° 向左打开至 −180°，内页始终留在原处。

封面姓名为朱敏在左、汪家喆在右。宽度超过 700px 时加入白色毛笔字“诚邀你，共赴我们的婚礼”，并放大姓名；手机保留原有字号和照片取景。封面采用两张独立的照片映射：竖屏手机使用原始 `5A8A6634.jpg`，桌面与横屏使用原始 `5A8A6627.jpg`。`<picture>` 保留响应式画面选择，这两张封面图独立于当前画廊第 03、05 张。

封面正反面同时使用 `backface-visibility` 与 `data-side` 切换可见性；封面背面为空白纸面，信文属于独立内页。`inert` 与 `aria-hidden` 随阶段同步。页首导航只在开场动画期间隐藏，内页没有移动或缩放。

开场手机约 1.9 秒、桌面约 2.4 秒。结束后停留原处，“继续读我们的故事”获得焦点且不触发滚动。滚轮、触控、滚动键或 Escape 可结束动画；减少动态效果立即呈现内页。客户端交互就绪前，`use-hydrated.ts` 禁用展信、跳过和保存入口。

内页继续按钮使用文字，右下角沿用全站同一个固定 SVG 箭头。两者都前往牵线引言；“直接看照片”前往第一张照片。姓名下的 Canvas 只画一条红线，标题与按钮的实测边界形成遮罩，使红线留在姓名与继续按钮之间。

## 完整阅读位置与手动接管

`hooks/use-reading-navigation.ts` 的 `readingStops` 统一定义：牵线引言、照片 01–05、黄昏中的相系、完整夜色中的相系、心意、圆满、正式邀请、时间与地点、请柬末尾。第五张照片之后先到 `tie-dusk`，即相系本章可滚动距离的 8%，红线仍然平展；再到 `tie` 的 82%，此时婚讯、结与邀请句完整呈现，82% 到 100% 进度始终保留原来的完整中国结。两个停靠点对应同一个 `#tie` 章节，减少动态效果时也保留这两个阅读状态。

`WeddingExperience.tsx` 的章节导航指向同一组停靠点，“03 / 相系”从黄昏开始。照片按整张卡片居中，顶部至少留 24px。高度不超过 620px 的手机上，心意停靠点距顶 8px，为两张纸页留出空间。手动下滚仍能阅读结绳与色彩过渡的全过程。

点击后通过 `requestAnimationFrame` 开始移动，时长按距离取 380–720ms。触摸开始、滚轮、滚动键或 Escape 会取消待执行帧与目标；只有正常到达才转移焦点，取消后没有延迟纠正或焦点跳转。两站之间点击箭头按当前滚动位置找下一站，动画中再次点击则推进到下一目标。信件弹窗打开前也取消移动。

`app/globals.css` 使用 `scroll-behavior: auto`，手动手势交给浏览器；`html` 与 `body` 设置 `overscroll-behavior-y: none`。滚动、视口变化和文档尺寸变化都会重新计算停靠点与到底状态，地图展开后末尾仍以真实文档底部为准。减少动态效果时按钮直接到达目标。

## 红线如何连成一条

红线分为两种绘制，交接依赖实际 DOM 坐标。`components/red-thread/line/stage.tsx` 测量章节、内页文字、结的位置及照片首尾锚点，向 `engine.ts` 提供滚动进度；`shapes.ts` 定义线、结和环的形态，`render.ts` 负责 Canvas 笔触。Canvas 在封面关闭时隐藏，展信后在姓名下绘制单线。

`PhotoThread.tsx` 在照片容器内绘制一条连续 SVG 路径，通过 `data-thread-photo` 与 `data-thread-card` 测量照片和完整卡片。照片旋转矩阵决定上下边缘的真实中心接点；红线从上方穿入纸面、从下方穿出。四处卡片留白分别使用 `loose-overhand`、`paired-crossing`、`soft-heart`、`open-oval`：松结、双线交叠、柔和心形与开口椭圆，其中心形位于粉色房间照之前，开口椭圆朝向后面的圆满。

`app/thread-path.css` 为每个完整线形留出独立间距，桌面卡片间距为 152px，手机为 140px。照片纸面遮住内部线段；`PhotoThread.tsx` 的 `clipPath` 使用 `clipRule="evenodd"`，在外层矩形内按五个字幕实测范围各外扩 8px 留出孔洞，避免红线穿字。`data-thread-entry`、`data-thread-exit` 向 Canvas 提供相同的交接端点。调整照片尺寸或排版后，应核对中心接点、四种线形、字区避让和窄屏外溢。

SVG 线使用弹性与阻尼传递滚动拉力，手机摆幅较小。Canvas 不通过 React 逐帧更新，像素倍率上限为 2；照片红线离屏暂停，页面隐藏暂停，减少动态效果停止持续模拟。照片与文字始终拥有阅读空间。

相系与圆满的文本和组件在 `components/red-thread/chapters/` 和 `components/red-thread/content.ts`。`app/fusion.css` 保持其局部字体平滑方式、消除同名 `.ring` 工具类阴影，并调整手机照片、心意与圆满尺寸。白昼纸色与夜色只做简单淡入淡出；`line/daylight.ts` 按对应背景亮度计算正文、次级文字与朱红前景色，保证过渡中可读。`stage.tsx` 将结果写入共享 CSS 变量，让最后一张照片字幕与红线章节同步变化。`app/dusk-ring.css` 在 `app/layout.tsx` 中最后加载，应用昼夜配色与减少动态效果下的相系状态。

圆满恢复为到达即完整的构图。`shapes.ts` 的 `ring` 直接生成两段互补半圆，`stage.tsx` 按正文位置测量圆心、半径和文字遮罩；`TheRing.tsx` 初始状态就是 `closed`。章节标记、邀请语与落款立即显示，正文保留完整布局和无障碍文本。箭头到达、直接滚入和重新进入都使用同一完整状态，手机、桌面和减少动态效果模式一致。

圆满没有局部计时、延迟显字或重播序列，也不在离场时变成其他线形。第三章中国结在 82% 到 100% 保持完整，随后随本章自然离开。修改配色或几何后，需同时检查生成颜色、实际文字可读性及结与圆环的形状。

阶段按 `overture → thread → tie → heart → ring → end` 测量。心意使用 `data-chapter="heart"`，正式邀请使用 `data-chapter="end"`；`stage.tsx` 分别将相系裁切到心意上边界、圆环裁切在圆满与正式邀请之间。心意纸页和最终邀请正文因此拥有独立空间。圆环跟随邀请语进入与退出，结也随相系离场，不在相邻章节悬留；夜色切换同步调整离场字幕颜色。

`engine.ts` 初始化及视口变化时从当前测量形态落定，滚动时搬移目标坐标并保留局部波动；大跨度跳转重新落定，避免红线从旧位置弹入。修改布局后核对开场单线、照片中心接点及各章节进出边界。

`assets/photo-originals/` 是画廊生成输入，`public/images/` 包含两张封面 JPG 和 16 个 WebP 变体；两者均由素材脚本准备并被 Git 忽略。完整输入以根目录 `assets/photo-map.json` 为准，生成记录写入 `assets/photo-variants.json`。

`scripts/prepare-photos.mjs` 使用 `sharp@0.34.5`，按四张竖图各 768、1280、1920px，第 05 张横图另加 2560px 生成 WebP，质量为 86、effort 为 5。文件体积取决于当前输入。运行 `npm run prepare:photos` 会先按当前素材模式准备输入，再生成变体；`npm run build` 每次自动执行同一步，封面 JPG 保持原样。

`Photo.tsx` 提供对应原图标识下的 WebP `srcSet`，`sizes` 根据卡片实际显示宽度选择资源。第 05 张横图在手机中被裁成较高的画面，以 `max(88vw, 67.5svh)` 计入所需完整宽度，保留人脸清晰度；默认 `src` 为 1280px 版本。原始宽高继续用于页面比例，画廊懒加载保留，所有照片及弹窗都异步解码，弹窗复用同一组响应式变体。封面仍按视口选择原来的两张完整 JPG。修改素材后核对原图标识、宽高、替代文本、变体清单、封面独立映射与实际窄屏显示。

每张照片或“读背面的信”只打开自己的纸笺，读完后回到该照片继续页面。顶部关闭按钮、Escape 和左下角带 SVG 箭头的“返回照片”均可收起，并通过 `finalFocus={noteTrigger}` 恢复原触发焦点；心意原信对应“返回心意”。`WeddingExperience.tsx` 在打开信件前取消仍在进行的按钮滚动，保持手机快速操作时的阅读位置。粉色纸笺的顶部内边距为 64px，避开右上角 54×54px 折角；姓名保持单行。

“04 / 心意”的两封原信独立于照片短笺，分别以“一纸短，情意长”和“致 · 亲爱的你”为题。`Correspondence.tsx` 将纸页放在稳定容器内，`use-paper-fan.ts` 观察容器以避免运动中的纸页反复触发自身动画。手机在双喜下方展开重叠纸页，桌面从中央带透视向两侧展开；键盘聚焦或减少动态效果时直接显示落定状态。

手机的粉色照片按视口高度缩小，心意章收紧标题、双喜和纸页之间的间距。高度不超过 620px 时，心意主卡的“囍”跨四行排列，姓名以 16px 单行显示，短笺正文为 14px；配合较小的照片与纸页，保留照片加字幕、心意全幅的完整阅读画面。圆满在手机上保持至少 `100svh`，邀请语居中，保留完整一屏。

`SaveInvitationImage.tsx` 按需生成并复用图片文件。支持文件分享时，图片就绪后的下一次点击直接打开系统菜单；其他环境提供预览、长按提示或下载。图片不依赖页面截图，因此尺寸与当前滚动位置不会影响成品。图片生成与保存入口见 [README.md](README.md)。

## 维护与验收边界

婚礼事实保存在 `lib/wedding.ts`，相系婚讯日期还写在 `components/red-thread/content.ts`。修改后同步核对封面、相系婚讯、正式邀请、元数据、地图和 PNG。地图按完整店名搜索，厅号独立显示；筹备 SOP 不随页面发布。

构建、字体维护、测试入口和独立部署见 [README.md](README.md)。照片和导出结果不纳入 Git；公开构建使用占位图。修改阅读导航或几何后，复查手机与桌面的封面、五封纸笺、照片连线、暮色与完整结、心意、圆环、地图以及邀请 PNG。需要同时检查减少动态效果、手动取消滚动和窄屏溢出；物理手机上的分享与地图唤起需单独验证。
